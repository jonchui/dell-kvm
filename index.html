How I built a true KVM with one keyboard and one mouse across my Mac and my PC

I have a MacBook Pro, a new Alienware, and one 34" Dell ultrawide between them. What I wanted was stupidly simple: one keyboard, one mouse, one monitor, and a hotkey to jump between the two computers. What I got, at first, was a night of "why is nothing working." Here's what actually worked, in the order I wish I'd done it.

The setup

  • Monitor: Dell U3419W (34" ultrawide, built-in KVM)
  • Mac: MacBook Pro M1 Pro, connected over one USB-C cable (video + power + USB)
  • PC: Alienware Aurora, connected over HDMI
  • Keyboard/mouse: Apple Magic Keyboard + Magic Trackpad

The one thing nobody tells you: your monitor is already a KVM

Most Dell UltraSharps have a KVM built in. The monitor has USB "upstream" ports (one per computer) and USB-A "downstream" ports (for your keyboard and mouse). The USB Selection menu in the OSD tells it: "when the picture is on input X, hand the keyboard to computer Y." Switch the picture and the keyboard follows. No software at all.

Which means the whole problem reduces to two things:

  1. Wire each computer's USB into the monitor.
  2. Make a keyboard shortcut switch the monitor's input.

Step 1: the wiring (this is where I lost an hour)

The Mac was easy: one USB-C cable carries video, power, and USB.

The PC needs two cables: HDMI for the picture, and a USB-A to USB-B cable from any USB port on the PC into the square USB-B port on the back of the monitor. That square "printer plug" is the cable everyone skips, and without it the monitor has no way to hand the PC your keyboard.

My mistake: I used a USB-A to USB-A cable with a B adapter on the end. It looks like it should work. It doesn't. USB is a one-way tree: A ports are on hosts (computers), B ports are on devices (the monitor's hub). A-to-A means host-to-host, which the spec doesn't even define, so those cables are either charge-only or contain a chip pretending to be two devices. Either way the monitor's hub never announces itself to the PC. I could see from Windows that no hub ever appeared, and from the Mac that the keyboard never left. A plain $8 printer cable fixed it instantly.

Then plug the Magic Keyboard into one of the monitor's USB-A ports with its Lightning cable. Wired, it acts as a plain USB keyboard for whichever computer the monitor points at. Unplug it and it's Bluetooth to the Mac again.

Step 2: the monitor menu (once)

Joystick → Menu → USB Selection. The U3419W lists it per video input:

  • HDMI 1 → USB 2 (the square port the PC's cable is in; there are two, labeled 1 and 2, so match them)
  • USB-C is implicitly its own upstream, nothing to set

Then Menu → Input Source → Auto Select → On.

Step 3: the hotkey, on both sides

The monitor speaks DDC/CI, a control channel over the video cable, so each computer can tell it "switch to input 17" (HDMI 1) or "switch to input 27" (USB-C). Each machine only needs to know how to leave, because once you switch, the keyboard is physically on the other computer.

On the Mac: m1ddc (Apple Silicon DDC tool) + Hammerspoon for the hotkey. Ctrl+Alt+1 → PC, Ctrl+Alt+2 → Mac, Ctrl+Alt+0 → toggle.

On Windows: NirSoft ControlMyMonitor + AutoHotkey, same three shortcuts. Ctrl and Alt on the Magic Keyboard are Ctrl and Option, so it's the same physical keys on both sides.

I packaged both into one-line installers:

macOS (Apple Silicon), in Terminal:

curl -fsSL https://raw.githubusercontent.com/jonchui/dell-kvm/main/install.sh | bash

Windows, in an admin PowerShell:

irm https://raw.githubusercontent.com/jonchui/dell-kvm/main/install.ps1 | iex

Different Dell or different ports? The input codes are variables at the top of each script (15 = DisplayPort, 17 = HDMI 1, 18 = HDMI 2, 27 = USB-C).

The detour I'd skip: software KVM

While waiting on the cable I set up Deskflow (the open-source Synergy fork), where the keyboard stays paired to the Mac and keystrokes get forwarded over Wi-Fi. It works, and it's the right answer if your monitor has no KVM. But it fights you in small ways: a non-elevated Windows client can't type into admin windows, two clients with the same name knock each other off, and every restart on the server side drops the session. The hardware path has none of that, and it works even when one machine is asleep.

What it feels like now

⌃⌥1: picture flips to the Alienware, keyboard and mouse come with it. ⌃⌥2: back to the Mac. That's it. Total hardware cost: one printer cable I should have had in a drawer.

The whole thing was debugged with Claude reading the Mac's USB tree and the monitor's DDC state over my shoulder while I plugged cables in, which is the part I'd actually recommend: having something that can see which computer the keyboard is on turns a guessing game into a two-minute test.
